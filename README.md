# Mino

**给菜单栏，留点空白。** A little less. Just right.

免费、开源、原生的 macOS 菜单栏管理工具。用一个分隔符，把低频图标收起来，常用图标留在眼前。

[English](README.en.md) · [下载预览版](https://github.com/levin8023/mino/releases) · [使用指南](docs/USER_GUIDE.zh-CN.md) · [参与贡献](CONTRIBUTING.md) · [MIT License](LICENSE)

> **0.2.0 早期预览版**：核心是分隔符折叠。尚未经过所有系统、刘海屏和多显示器组合的验证。已知限制见下方。

macOS 27 自带 `>>` 收纳入口，任何第三方图标（包括 Mino）都可能被系统收进去。请先按住 `⌘` 把主按钮和分隔符排好顺序。完整分区效果仍需实机确认，详细结果见 [验证记录](docs/VERIFICATION.md)。

## 功能

- **点击展开 / 收起**：将分隔符左侧图标移出可见区域。
- **始终隐藏区**：偏好设置可启用；普通展开不会显示，只通过专用菜单临时展开。
- **原生整理方式**：按住 `⌘` 拖动系统菜单栏图标，无需学习新的布局编辑器。
- **全局快捷键**：`⌃ ⌥ M`，可关闭，注册冲突会提示。
- **自动收起**：3–60 秒可选；使用菜单栏、整理模式和设置窗口打开时暂停。
- **登录时启动**：使用 macOS `SMAppService`，默认关闭，由用户开启。
- **中英双语**：默认跟随系统，也可立即切换。
- **保护操作入口**：分隔符在控制按钮右边时拒绝折叠；显示器变化或唤醒后先展开。
- **本地优先**：无账号、无广告、无统计、无应用发起的网络请求、无第三方依赖。

基础功能不申请辅助功能、输入监控或屏幕录制权限。

## 系统与安装

部署目标为 **macOS 13+**，支持 Apple silicon 和 Intel。最低系统版本是构建目标，不代表已完成每个版本的实机测试。

从 [Releases](https://github.com/levin8023/mino/releases) 下载适合的 ZIP，解压后将 `Mino.app` 拖入 `/Applications`，双击启动。应用常驻菜单栏，不显示 Dock 图标。首次启动会打开使用向导。

预览包使用 **ad-hoc 签名**，尚无 Apple Developer ID 签名及公证，macOS 可能阻止直接打开。只在确认来源和校验和后，按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 在系统设置中处理；也可在本机从源码构建。不提供关闭 Gatekeeper 的脚本。正式分发签名流程见 [发布指南](docs/RELEASING.md)。

校验下载文件：在下载目录执行 `shasum -a 256 -c Mino-0.2.0-universal.zip.sha256`。

## 第一次使用

1. 暂时退出其他菜单栏管理工具，避免多个分隔符互相影响。
2. 在 Mino 窗口中点「整理图标」。窗口会暂时隐藏，自动收起暂停。
3. 按住 `⌘`，将低频图标拖到 **Mino 分隔符左侧**。三根高低竖条形状的控制按钮必须留在分隔符右侧。
4. 右键 Mino，选择「完成整理并收起」。之后点击 Mino 或按 `⌃ ⌥ M` 切换。

展开时，从左到右示意如下（分隔符使用竖向三点 ⋮）：

```text
[偶尔使用的图标]  [分隔符]  [▂▅█]  [常用图标]  [系统项目]
       可收起区域             始终保留在可见区域
```

主按钮只显示原创三竖条图标（无文字），分隔符为 `⋮`。两者均支持右键菜单，提供使用说明、设置和退出；`⌥` 点击主按钮打开设置。重新打开应用也能显示设置窗口。退出 Mino 会移除分隔符，释放空间；第三方图标的实际位置仍由 macOS 管理。

## 始终隐藏与 macOS 27

在偏好设置开启「始终隐藏分区」，然后按住 `⌘` 从左到右排列：

```text
[始终隐藏图标] [锁形分隔符] [普通隐藏图标] [⋮] [三竖条主按钮] [常驻图标]
```

开启时会进入整理模式；右键完成整理。日常点击和快捷键只切换普通隐藏区。需要访问始终隐藏区时，右键选择「临时显示始终隐藏区」；再次选择可单独重新隐藏。开启自动收起时，临时显示也会在空闲后结束。

macOS 27 的 `>>` 是[系统自带的溢出收纳功能](https://support.apple.com/en-eg/148830)。Mino 使用受限宽度分隔符适配这一行为；图标可能进入系统收纳。若主按钮也在其中，展开 `>>` 后按住 `⌘` 将三竖条图标移向常驻侧。Mino 无法通过公开 API 关闭系统收纳或保证任何图标永不进入其中；「始终隐藏」指 Mino 的日常切换行为，不是隐私隔离。

## 从源码构建

需要 macOS、Swift 5.9+ 工具链（Xcode Command Line Tools 或完整 Xcode）。无远程 Swift 包依赖。

```sh
git clone https://github.com/levin8023/mino.git
cd mino
./Scripts/test.sh
./Scripts/build.sh
open build/Mino.app
```

脚本将所有构建缓存保存在 `.build/`，生成 `build/Mino.app` 并验证 ad-hoc 签名。包名、版本号和部署目标分别位于 `Resources/Info.plist` 与 `Package.swift`。完整 Xcode 可直接打开 `Package.swift`，最终分发仍使用脚本打包。

通用二进制和 ZIP：

```sh
ARCH=universal ./Scripts/package.sh
```

输出 `dist/Mino-0.2.0-universal.zip` 和 SHA-256 文件。`build/`、`dist/`、密钥和个人 IDE 文件均不进入 Git。

## 工作原理与限制

Mino 只控制它自己创建的两至三个 `NSStatusItem`，通过增大分隔符宽度，让左侧项目因空间不足而溢出；不会修改第三方应用进程或使用私有 API。**跨应用隐藏效果依赖 macOS 菜单栏排布行为，并非 Apple 保证的第三方图标管理 API**，未来系统版本可能改变效果。

- 刘海、应用菜单和屏幕宽度仍可能挡住展开的图标。**当前没有独立图标浮窗**。
- 暂无图标搜索、自动移动第三方图标、按应用配置规则、云同步和自动更新。
- 某些系统图标无法 `⌘` 拖动；Mino 无法绕过系统限制。
- 多显示器由 macOS 管理，尚不提供每个显示器独立的分区配置；切换显示器、Space、全屏时需要人工验证。
- 自动收起仅在指针离开屏幕顶部 400 点范围后计时。无法可靠识别其他应用打开的所有菜单；长菜单中操作时可关闭自动收起。
- 整理模式持续到选择「完成整理并收起」，期间自动收起暂停。
- 登录项需将 `.app` 放在固定位置后启用。本机移动应用、签名变化或系统审批都可能影响注册。
- 当前只有固定快捷键，冲突时可禁用；自定义快捷键在路线图中。
- 设置窗口打开时暂停自动收起，但仍可主动点击按钮或使用快捷键收起。

设计、测试边界和后续计划见 [架构说明](docs/ARCHITECTURE.md)、[验证清单](docs/TESTING.md) 和 [路线图](docs/ROADMAP.md)。
